# Tax Alphonic CMS admin panel

React SPA used by editors to manage the Tax Alphonic website content. It talks only to the backend `../tax-alphonic-backend-by-ravi` (see that CLAUDE.md for the API). The public website that renders this content is `../taxalphonic-dynamic-frontend` (Next.js); the old `Desktop\tax\taxalphonic` copy is no longer used.

## Stack and commands
- Vite + React 19, react-router-dom 7, react-bootstrap / Bootstrap 5 + bootstrap-icons, TanStack Query and Table, react-hook-form, TipTap and Jodit editors, chart.js, react-toastify.
- `npm run dev`, `npm run build`, `npm run lint` (oxlint). Not a git repo. No tests.
- `.env`: `VITE_API_URL` (default `http://localhost:5000/api/v1`), `VITE_APP_URL` (points at the backend), and `VITE_SITE_URL` (the Next.js website, default `http://192.168.0.166:3000`, used by Live Preview).

## Layout
- `src/App.jsx` holds all routes. Admin routes sit inside `<ProtectedRoute>` + `AdminLayout`, and each one is wrapped in `<RoutePermission action module>` (modules match the backend `checkPermission` names). The sidebar comes from `src/config/menuConfig.js`.
- `src/services/api.js`: the axios instance. It attaches `Bearer` token from local/sessionStorage, and on 401 it clears the token and redirects to `/login`. Per-domain wrappers are in `src/services/*.service.js`, though some pages call `api` directly.
- `src/pages/`: one `XList.jsx` + `XForm.jsx` pair per entity, plus folders (`blogs/`, `crm/`, `forms/`, `logs/`, `About/`, `Settings/`, `auth/`).
- List tables: `src/components/datagrid/DataGrid.jsx`. A column with id `actions` is always pinned to the right (sticky) and kept last. Row buttons come from `ActionColumn.jsx`, which also shows a History button (`RecordHistory.jsx`: `GET /audit-logs?recordId=`, visible only with `read AuditLogs`). Pages with hand-written action cells add `<HistoryButton>` themselves. Plain Bootstrap tables use the `sticky-actions` class on the actions `th`/`td`.
- Page Builder: `src/components/page-builder/PageBuilder.jsx` and `SectionRenderer.jsx` (one editor per block). `src/components/page-builder/blockFields.jsx` has shared field editors: `TextField`, `ButtonField` (`{text,url}`), `RepeaterField`, `SelectField`.
  - `AVAILABLE_BLOCKS`: HeroBanner, Overview, WhyUs, Faq, ServicesIncluded, OurProcess, Form, Packages.
  - With the `layoutSettings` prop (`ServiceForm.jsx`, and `PageForm.jsx` for every page except the homepage), the builder also offers `SERVICE_BLOCKS` (Highlights, Checklist, CallToAction) and a per-block `BlockSettings` panel.
  - `BlockSettings` writes `section.config = { placement, kicker, anchorId }`. `DEFAULT_PLACEMENT` (in `layoutZones.js`) must match the website's `ApiServicePage.jsx`.
  - Layout canvas (service pages and the homepage): `layoutZones.js` turns the flat section list into areas and back. Service: Hero, Top, Main | Right sidebar, Bottom. Homepage: rows in page order, each either full width or Main | Right sidebar (plus one empty row at the end to drop into). Blocks are dragged between areas, or from Available Blocks into an area (the + button still adds). A drop sets `config.placement`; a block that does not fit is refused with a toast (`serviceDropError` / `homeDropError`): the hero stays on top, the service sidebar takes only `SERVICE_SIDEBAR_BLOCKS` (Form, Highlights, Checklist, CallToAction), and the home columns follow `HOME_PLACEMENT_RULES`. In a two-column area the open block's editor shows full width under the row. Plain pages and blogs keep the single list.
  - Blogs use the builder without these options (one plain list). Pages get them because the website renders a page with blocks in the service-page layout.
  - Home Page Builder: `blockSet="home"`, used by `PageForm.jsx` when the page slug is `home` (or `/pages/new?template=home`). `/pages/home` (`HomePageEditor.jsx`, also in the sidebar and on PagesList) opens that page or starts it prefilled. Blocks and field schemas live in `homeBlocks.js`, default content in `homeDefaults.js` (identical to the website's `components/tax-alphonic/home/homeDefaults.js`). They are edited through the generic `SchemaFields.jsx`, whose field types are text, textarea, select, button, list (checkbox/colour columns), group, form (a CMS form picker that sets `payload.formId`) and portfolioCategory (sets `payload.categoryId`). The "Portfolio" block (`HomePortfolio`) shows the Portfolio module on the homepage; its "Show this section" select (`show: hide`) takes it off the site without deleting it. "Reset to default layout" replaces all blocks.
    - Field types also include `select`, `note` and `image` (Media library picker with preview, stores the media URL), and any field can set `showIf`.
    - Hero: optional right-side image (`heroImage`, replaces the dashboard visual) and a size select (`visualSize`).
    - Placement (`BlockSettings` with `home`) appears only on blocks listed in `HOME_PLACEMENT_RULES` (`homeBlocks.js`), with only their allowed options. The Form block defaults to the right sidebar and the other listed blocks to Main content, so blocks next to a form fill the left column (service-page style); "Always full width" ends a row. The hero and other wide blocks have no option. Keep the map in sync with the website's `PLACEMENT_RULES`.
    - Testimonials, FAQ and Clients have a Content switch: from their CMS module (default) or manual.
    - The Form block (`HomeForm`) picks any active CMS form; submissions land in CRM Leads.
    - Team, Banners, Branches and Global Presence only read their module (`/cms/team`, `/cms/banners`, `/cms/branches`, `/cms/countries`). The website renders them in `components/tax-alphonic/home/HomeSections.jsx` with the `uirefrence.html` home design.
- Blocks in every builder: the palette (with search) shows the builder's own blocks, then "General blocks" (`commonBlocks.js`: CommonText, CommonImageText, CommonImage, CommonVideo, CommonGallery, CommonStats, CommonCards, CommonLogos, CommonButtons, CommonSpacer, CommonEmbed; schemas for `SchemaFields`, defaults in `commonDefaultPayload`) and, outside the Home builder, the homepage sections (every `Home*` block except HomeHero). New blocks get their default payload whatever the builder (`defaultPayloadFor`). On service pages, Home blocks go to the Bottom area and common blocks to Main by default (`servicePlacementOf`); neither fits the service sidebar. Types must match the website's `components/tax-alphonic/blocks/commonBlockTypes.js` / `CommonBlocks.jsx`.
- Background panel (`BackgroundSettings.jsx`) on every block of every builder, heroes included: `section.config.background = { color, image, position, size (cover|contain|repeat), fixed, overlayColor, overlayOpacity 0-100, textTheme (light|dark), padding (none|sm|md|lg|xl), rounded }`. No colour and no image = the block's own design. "As designed" text turns white on a dark overlay / colour. The service Hero has "Right-side image" (`imageMode`: auto | custom | none); auto uses the service thumbnail only when the hero has no background. Rendered by the website's `blocks/BlockBackground.jsx` (keep keys in sync).
- `PageForm.jsx` has a Builder / Live Preview switch on every page, using the same pane: `kind="page"` with `{ title, content, sections }`, `kind="home"` with `{ sections }`, `kind="journey"` with `{ title, slug, sections }`.
- Journey Stage pages (uirefrence.html `#/journey/<stage>`, the homepage "Idea to Revenue" cards link to `/journey/idea` … `/journey/revenue`): a CMS page with slug `journey/<key>` built from Journey blocks (`blockSet="journey"`, one full-width list; `isJourneyPage()` turns PageForm into journey mode: Stage URL box, no content editor). Blocks, field schemas and the shared reference texts are in `components/page-builder/journeyBlocks.js` (rendered by `SchemaFields.jsx`, which also has a `color` field type); the 10 reference stages (content, links mapped to website routes) in `journeyReference.js`, generated from uirefrence.html. The Stage Hero block defines the stage (number orders it, colour / icon used by every block); "{stage}" in any text becomes the stage title, "{read}" in the hero chips the reading time. Progress, Roadmap, Flow and Previous / Next have no content: the website builds them from `GET /pages/journey-stages`. New blocks land at their reference position; "Fill from template…" replaces the page with the empty template or a reference stage. PagesList → Journey Stages: new stage, new from a reference stage (`/pages/new?template=journey&stage=idea`), or create all 10 reference stages as drafts (existing slugs skipped). Sidebar CMS → New Journey Stage. Website side: `components/tax-alphonic/journey/JourneySections.jsx` (BLOCKS map must match `JOURNEY_BLOCKS`).
- Free tools (uirefrence.html `#/tools` hub and `#/tool/<key>`; the homepage Free Tools block links to `/tool/gst-calculator` …): CMS pages built from Tool blocks (`blockSet="tool"`, one full-width list; `isToolPage()` turns PageForm into tool mode with a Page URL box: `tool/<name>` for a tool, `tools` for the hub). Blocks / schemas / texts in `components/page-builder/toolBlocks.js`, the 7 reference tools (income tax, GST, HSN, HRA, SIP, GSTIN, EMI) in `toolReference.js`. The Calculator block (`ToolCalculator`) picks the calculator and holds its settings (tax slabs, rebate / cess / surcharge, GST rates, HSN list, state codes, defaults); its fields depend on the chosen calculator (`TOOL_SCHEMAS.ToolCalculator` is a function, see `toolSchemaFor`) and switching the calculator loads that calculator's defaults. Defaults come from the website's `components/tax-alphonic/tools/toolDefaults.js` through the preview copy (`src/site-preview/website/...`), so run `npm run sync-preview` after changing them. ToolsGrid (hub) and ToolMore list the published tool pages by themselves (`GET /pages/tools-list`, ordered by the Tool Hero's Order). ToolForm picks a CMS form (CRM lead). PagesList → Free Tools: new tool / hub, new from a reference tool (`/pages/new?template=tool&tool=gst-calculator`, `&tool=hub`), or create the hub + 7 tools as drafts. Sidebar CMS → New Free Tool.
- Live Preview (Service, Page and Home builders): `src/components/page-builder/ServicePreviewPane.jsx` → `src/site-preview/SitePreviewFrame.jsx` renders the unsaved draft **inside the admin** with the website's own components; no website needs to run or be deployed. Desktop/tablet/mobile widths, website dark mode toggle, reload (clears the 60 s GET cache). The site code is a verbatim copy in `src/site-preview/website/` made by `npm run sync-preview` (`scripts/sync-site-preview.mjs`, website path `SITE_SOURCE_DIR`, default `../taxalphonic-dynamic-frontend`; it follows imports from `servicePreview.js`, `ApiServicePage`, `ApiPage`, `HomeSections`). Never edit that folder: change the website, then re-run the sync. `src/site-preview/vitePlugin.js` makes the copy run in Vite: `@/` paths, `next/link` / `next/navigation` / `next/headers`, `apiClient` (browser fetch to `VITE_APP_URL`) and `formSubmission` (never submits) come from `src/site-preview/shims/`; the copy's own CSS imports are emptied and its stylesheets (`website/styles.js`, Tailwind compiled by `@tailwindcss/vite` from the copy only) go into the iframe, so nothing leaks into the admin; `window.`/`document.` are pointed at the frame. Header and footer are not shown. A new npm package used by the website renderers must also be installed here.
- `ServiceForm.jsx` sends sections as `{ sectionTypeId: <componentKey>, sortOrder, config, data: { payload } }`.
- The website renders only what the blocks contain (no fallback copy). An empty text field hides that element.
- Footer: there is no separate editor. The website footer shows the menu with location `footer` (Menus & Navigation), up to three levels: Main heading (section title) → Column heading → Link. A top-level link with only links under it is one column; one with nothing under it goes to the bottom row; a link titled `+…` is the blue "more" link. `MenuBuilder.jsx` edits the tree with `src/components/menus/MenuTree.jsx` (3 levels for the footer menu, 2 for others; column links fold). On the footer menu it also shows the Footer Display card (`FooterDisplaySettings.jsx`): show/hide and texts for logo, intro, button, hiring strip, column title, contact, social and copyright, saved as `menu.settings` (JSON). Defaults in `src/components/menus/footerDisplay.js` must match the website's `components/layout/footerDefaults.js`.
- Organization logos drive the website: Light Logo = header in light mode and the footer badge, Dark Logo = header in dark mode, Logo = fallback, plus Favicon / Apple Touch Icon.
- Hand-made `position: fixed` modals (MediaPickerModal, AiGenerationModal) render through `createPortal(..., document.body)` for the same reason: opened inside the Page Builder they were pinned to a transformed container (shifted, half backdrop). Do the same for any new custom modal.
- Editor Save buttons: every editor's header (breadcrumb, title, Save / Cancel and other page actions) is the sticky `.ta-editor-bar` (`assets/scss/global.scss`), so the buttons never scroll away and sit in the same place on every form. New editors use `components/common/EditorBar.jsx` (or add the class to their header) and keep no second Save at the bottom; a Save outside the `<form>` submits it with `form="<form id>"`. `AdminLayout.jsx` writes the bar's height to `--ta-sticky-offset` on `<main>`; other sticky panels use `.ta-below-bar` (or that variable) to sit under it (Page Builder blocks panel, Form Builder, SEO side cards, pSEO section nav).
- Page Builder drags: the dragged copy is portalled into `<body>` (`inBody` in `PageBuilder.jsx`) because transformed ancestors (e.g. `.tab-pane-transition`) offset `position: fixed`. That animation uses `backwards` fill for the same reason.
- Image upload sizes: `src/config/imageSizes.js` (`IMAGE_SIZES`, `imageHint()`) holds the recommended size/ratio/format for every image, taken from how the website renders it; `components/common/ImageSizeHint.jsx` shows it under the image fields (Settings, Banners, Partners, Countries, Team, Testimonials, Services, SEO, Blogs, Portfolio, About, Page Builder hero/logo fields). Update an entry when the website layout of that image changes.
- SEO Pages list (`/seo-pages`, `SeoPagesList.jsx` + `.css`): server-side from `GET /seo-pages/admin-list` (no page bodies; `counts` feed the six view cards: All, Live, Drafts, Need AI content, AI written, Archived), type and service filters, search on title/slug. Bulk bar (`DataGrid` `bulkActions`): Publish / Draft / Archive via `POST /seo-pages/bulk-status` (pages without content are never published), Write with AI for up to 20 selected pages (`bulk-generate-ai` with `ids`, `AiGenerationModal selectedCount`), Move to Trash.
- Matrix Combinator (`/seo-pages/new`, `SeoPageForm.jsx` + `.css`): step 1 service, step 2 four checkbox panels (Locations grouped by state, Industries, Technologies by category, Problems by type) with search, group filter, tick-a-group, Select shown / Only new / Clear and selection chips; step 3 review table (All / New / Skipped, search, shows 100 then more); sticky summary with the Create button (confirm above 50 pages). Existing combinations come from `GET /seo-pages/combos` (ids + slugs only). Inactive masters are hidden. Pages are created as DRAFT, noindex, without content.
- SEO Pages (pSEO, `/seo-pages`): a page is live on the website at `/<slug>` only when PUBLISHED with content; the list and edit form link to it (`src/config/siteUrl.js`, `VITE_SITE_URL`) and the edit form has the `indexable` switch (off = noindex). Service + location slugs are `<country>/<service>-<location>` (backend bulk-generate; `SeoPageForm.jsx` previews the same).
- pSEO content editor: `SeoPageEditForm.jsx` (`/seo-pages/edit/:id`) opens on the Visual Editor tab (`components/seo/SeoContentEditor.jsx` + `.css`), with HTML Source and Preview tabs beside it. One card per `<section data-section>`: heading, paragraphs (small TipTap box), cards / steps / figures (icon class, title, text; add / move / remove), FAQs and CTA button text + link, plus a per-section Edit HTML switch for anything else. `components/seo/pseoContent.js` reads and edits the HTML through DOMParser, changing texts and items in place so tags, classes and `data-section` stay as the website parser expects. The rich-text boxes are uncontrolled and remount (key) after AI regenerate (`resetKey`) or structural changes. Unsaved edits show in the sticky save bar and warn on tab close. HTML Source tab and each section's Edit HTML use `components/common/code/HtmlCodeEditor.jsx` (Monaco, lazy-loaded, bundled locally via `monacoSetup.js` with `?worker` imports): VS Code look, format (text kept on one line), find/replace, folding, minimap, theme/font size (remembered in localStorage `ta-code-editor`), full screen (portal), Ctrl+S = save and stay, Tailwind class suggestions inside class="…" (`tailwindClasses.js`). A section's HTML draft is applied 0.5 s after typing stops. Preview tab = `components/seo/TailwindPreview.jsx`: sandboxed iframe with the Tailwind Play CDN + Bootstrap Icons, desktop / tablet / mobile widths, grows with its content.
- SEO Configs (`/cms/seo`, `SeoForm.jsx`): pick the page (Service / CMS Page / pSEO Page / Homepage-About / Custom URL) instead of typing a URL; the page's own SEO shows as placeholders ("Copy this page's current SEO" fills them). Fields set here override that page's SEO on the website; empty fields keep it. Old rows without a type show "Not linked" and are ignored until edited.
- Menus: each item's editor (`components/menus/MenuTree.jsx` `IconInput`) takes an icon (emoji, or a square image from Media); `MenuBuilder.jsx` sends it as `icon`. Empty = the website's default icon (`DEFAULT_MENU_ICON`, same as the website header).
- Header menus allow three levels too (menu → link / column heading → link); the first five header items show in the website's top bar.
- Dashboard (`/`, `pages/Dashboard.jsx` + `Dashboard.css`, scoped `.ta-dash`): one call to `GET /dashboard/stats`; KPI cards, enquiries chart (7/14/30 days) and lead-status doughnut, "Needs your attention" list, latest enquiries, a tile for every module (count + live/draft), lead sources / top forms, recently updated services, audit activity, media & storage, shortcuts. Every number links to its list (`/services?status=draft`, `/crm/leads?status=NEW`, ...); tiles / panels are hidden when the user lacks that module's read permission. Chart configs are memoised and `animation: false` (animated charts froze half-drawn).
- Blog engagement: `/blogs/dashboard` (`BlogDashboard.jsx`) shows views / likes / comments / pending cards, the Top Posts chart with Views (left axis) plus Likes and Comments (right axis), and a 30-day likes & comments bar chart. `/blogs/comments` (`BlogComments.jsx`, sidebar Blog → Comments) moderates website comments: tabs by status, search, approve / hide / delete.
- Trash (`/trash`, `pages/Trash.jsx`, sidebar rail item): tabs per module with counts, search, restore / delete forever (single or bulk). `?module=services` opens a tab; the Services and Pages lists link to it. A deleted Media folder shows under "Media Folders" with what it holds (`detail`) and comes back with its subfolders and files.
- Media: `/media/settings` (`pages/media/MediaSettings.jsx`) picks where uploads are stored (project folder by default, or a cloud provider after Test connection). In the library a card / row click opens `components/media/MediaPreviewModal.jsx` (full size, details, alt text, copy / download, ← →); the checkbox selects. Build file URLs with `utils/mediaUrl.js` (`mediaUrl()` keeps full cloud URLs, prefixes local /uploads paths with VITE_APP_URL). Modals sit above the sidebar via `--bs-modal-zindex` in `assets/scss/global.scss`.
  - Folders: every folder (sidebar tree and the tiles above the files, `FolderTiles.jsx`, with an All Media / A / B path bar) has a ⋮ menu (`FolderMenu.jsx`): New subfolder, Upload folder here, Rename (`PUT /media/folders/:id`), Delete (to Trash with its subfolders and files). Upload → "Upload folder" (or dropping a folder on the library or on a folder tile) recreates the local folder tree: `uploadFolder` in `MediaLibraryContext.jsx` reuses a same-named folder under the same parent, creates the rest, and posts files 10 per `/media/upload/bulk` call with progress. `components/media/folderUpload.js` reads the picker / drop and skips unsupported types, files over 50 MB and OS clutter (.DS_Store, Thumbs.db).
- Long dynamic dropdowns use `components/common/SearchableSelect.jsx` (search, keyboard, groups, `emptyLabel`, `sub` text, loading); plain `<select>` only for short fixed lists.
- Image fields always offer the Media picker (`components/media/MediaPickerModal.jsx`: pick, or "Upload new" to the active storage into the open folder; double-click inserts). Use `MediaPickButton` (a button returning the URL) or, in the Page Builder, `TextField media` / `MediaTextInput`; `RepeaterField` and schema text fields named icon / image / logo / avatar / photo get it automatically (`MEDIA_KEY` in blockFields.jsx). URL validations must accept Media paths (`/uploads/...`) as well as https URLs.
- Server-side lists: backend list APIs (BaseService) return only `limit` rows (default 10), so a list must page on the server. `components/datagrid/useServerList.js` (`fetchData` for DataGrid: page / limit / sortBy / sortOrder / `<field>_like` search, both response shapes, stale responses ignored) and `MasterList.jsx` (the pSEO masters: States, Locations with state filter, Industries, Technologies, Problems) use it. DataGrid sends the search 300 ms after typing stops and goes back to page 1 on a new search. Dropdowns that need every row ask for `limit: 1000`.
- Bulk delete: `DataGrid` takes `deleteUrl` (+ `deleteMode` "trash" | "permanent", `itemLabel`); the bulk bar then opens the themed `components/common/ConfirmDialog.jsx`, deletes each selected row (`DELETE ${deleteUrl}/${id}`), toasts the result (failures with the API's reason) and reloads via `fetchData`. Every list with row checkboxes passes it; never use window.confirm: call `await confirmDialog({ title, message, items, note, tone, confirmText })` or `await confirmDelete(name, { trash, what, extra })` from `components/common/confirm.js` (rendered by `ConfirmHost.jsx`, mounted in App.jsx). Every delete / reset confirmation in the admin uses it.
- `LocationsServed` ("Locations We Serve") is a Service Page Builder-only block (`blockSet="service"` in `ServiceForm.jsx`): heading, sub-heading (`{service}`), count badge (`{count}`), show yes/no. The website adds it automatically when absent, so the block only overrides texts/position.
- Forms builder: `src/pages/forms/FormBuilder.jsx`. `src/components/forms/FormPreview.jsx` shows how the website renders a form, and `formEmbed.js` lists the public endpoints.
- Packages: `src/pages/PackageForm.jsx`. `features.collapsedCount` is the number of feature sections shown before "show all". `keywordTiers` is an alternative to flat `pricingPlans`.

## Adding a Page Builder block
It touches all three projects:
1. Admin: add it to `AVAILABLE_BLOCKS` and add its editor in `SectionRenderer.jsx`.
2. Backend: add the section type (`componentKey`). If the block references other records, add a `SectionHydrator` entry.
3. Website: add a case in `BodyBlock` in `components/tax-alphonic/pages/ApiServicePage.jsx`.
